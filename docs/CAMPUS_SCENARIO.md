# 校园资料回归

这个场景用于检查“资料是否选对、原文能否核对、缺资料时是否停止”。它使用真实历史资料，但执行端是离线词法基线，没有调用学校服务或 LLM。

## 数据从哪里来

`datasets/campus/sources/manifest.json` 记录 8 份用户已有 RAG 知识库文档的来源，`corpus/` 保留经过筛选的 Markdown 摘录。原始 DOCX 不随仓库发布。每份来源记录：

- 相对于原知识库的文档路径与原文件 SHA-256。
- 摘录 SHA-256、年份、明确写出的年级、校区。
- `word/document.xml` 中所有 `w:p` 的一基序号，包含空段和表格段；不是 Word 显示页码。

年份与年级分别保存。计算机和人工智能只标注“2024版”，所以 cohort 为 null，不推断为“2024级”。导航特色班原文出现“中午14点”的措辞，保留原文，不替学校改写。

这些文件是历史摘录，未联网确认现行政策。未附电话、邮箱、名单、账号或整库二进制。原文权利归原作者，仓库 MIT 只适用于代码和原创部分。

## 数据与评分怎么分开

`scripts/build_campus_dataset.py` 存放人工编写的问题与引用段落索引。运行前检查 Markdown 摘录的 SHA-256，并核对 manifest 段落确实出现在对应摘录中。输出 `datasets/campus.json`，可逐字节重建。

每个案例的 fixtures 携带同一份候选资料快照和调用方明确提供的校区/年份范围。它不携带答案标志；原文自然包含事实，是检索输入，不是评分字段。Runner 在传给 Adapter 前清空 expected_answer、expected_tool_sequence 和 assertions，评分使用保留的原始案例。

`campus_evidence` 先按范围过滤，再用中文二元字符与英文词的覆盖率排序，最多读取两份来源。它返回带文档编号和段落编号的原文，没有语言模型。规则简单、便于复查，无法可靠处理复杂语义、跨文档推理或范围信息缺失。

`source_quote` 要求已知文档编号及该来源的完整原文；另一条 contains 断言要求指定段落标记。拒答案例则检查拒绝提示与仅执行 search 的工具序列。14 条可回答案例未指定唯一工具路径，因此工具选择指标的分母只有 3 个拒答案例；不会把缺少工具参考的案例算作正确。

这套检查适合测引用输出规则，不适合直接评价生成式回答。原文引用之外的自由文本、相似改写和矛盾附加声明不在其能力范围内，接生成式 Agent 后应增加事实级评分与人工抽检。17 条问题也不能作为独立保留测试集或模型能力基准。

## 运行与核对

```bash
make campus-demo
make campus-serve
```

- `runtime/campus.db`：实际执行的 SQLite 数据；校园 Demo 对已审查的固定摘录显式保留正文。
- `runtime/campus.json` / `.jsonl`：同一执行的本地导出，仍经过公共凭证模式脱敏。
- `reports/campus-regression.json`：数据摘要、run ID、完整指标分母、逐案结果与原文件指纹。
- `reports/campus-regression.md`：便于阅读的逐案列表。

重复运行追加新的 run，不覆盖数据库历史；同名报告更新为最新运行。token/费用为 null，因为没有模型调用；本地规则执行耗时不能用于推断真实模型速度。

校园数据与 `datasets/synthetic.json` 相互独立。前者检查资料范围和引用，后者检查工具选择、恢复、并发执行和统计比较，不把两者的通过率混合成一个数字。

校园 Demo 使用 `sensitive_trace=True`，让工作台能够显示已审查的问题与原文输出；它只运行仓库内的固定校园数据集，不接受外部文件路径。通用 CLI 的默认脱敏行为保持不变，新增个人资料时不能沿用这个演示设置。
